# WiseLife 每日回顾

类型：当前产品与技术说明。状态：已实现，验证范围见下方。更新：2026-11-03。适用：WiseLife iPhone 的昨日、历史日期回顾。

关联：[文档索引](../../../apps/wrist-notes/docs/INDEX.md)、[本次窗口与等待状态验证](../../../apps/wrist-notes/verification/2026-10-23-persisted-timeline-recap-refresh.md#recap-budget-20261102)。

依据 `apps/wrist-notes/prototype/iphone-day.html` 与 `daybook.js`，实现原生回顾。

- 今天首页展示昨日回顾，历史日展示当天回顾。「我的记录」增加回顾筛选，跨日期倒序归档、关键词与日期搜索。点击卡片查看全文、生成时间、来源，打开原始记录。
- 回顾综合生活、工作与学习事项，可包含最多两条有证据依据的跟进建议；不自动执行建议。与每日洞察独立；一条有效记录即可生成。没有记录、转写未就绪、生成中、生成失败、外部发送待确认均有状态。
- 使用设置中的 AI；Apple 本地模型必须检查可用性与语言。自定义模型和 ChatGPT 共用现有确认与「下次不再提示」规则，不静默切换服务。
- 对完整日期范围读取内容片段和录音会话，独立于 UI 分页。包含全部获准记录的有限摘录；长文本使用开头、中间、结尾摘录，明确说明覆盖限制。每次模型请求有界，分批归纳后合并，保留来源编号。
- 来源权限与录音期间暂停生效。异步生成必须核对日期资料、配置版本、语言、授权；取消或变化后的返回不可保存。
- 本机 SQLite 按自然日存储回顾、来源摘要指纹和生成信息，不存原始转写副本，无 30 天裁剪。沿用数据库文件保护及排除云备份规则。
- 新增资料保留旧版并标记待更新；删除、修改或撤回来源权限时清除受影响的旧文。读取失败不能解释为记录删除，也不能把未验证的旧文显示出来。
- 自动处理昨日与当前浏览的历史日；更早未生成日期在用户打开后补生成。前台空闲执行，返回前台可补处理，不承诺午夜后台运行。失败记录不在定时刷新时反复发送，用户可以重试。
- 每个自然日只自动尝试一次：SQLite `daily_recap_attempts` 在任何异步调用前原子登记。成功、失败、超时、取消、资料更新、模型切换与重启均不恢复自动次数；后续只能手动生成。删除旧档案也不恢复自动次数。
- 验证分别记录自动回归、构建、模拟器和真机；不能以 stub 通过代替真机模型验收。

## 持久化读取与处理进度（2026-11-03）

- 回顾正文、生成时间、来源引用保存在 `daily_recaps(day PRIMARY KEY, payload)`；自动尝试登记独立保存在 `daily_recap_attempts`。存在日期行不等于已有正文，未生成／失效日期也可以保留占位档案。表结构和每日一次自动尝试规则不变，不需要迁移。
- 普通 ASR／分段进度、生成标题或摘要不触发历史档案全文重读。可见事实、日期范围与来源权限未变时，复用已准备的证据投影和指纹；比较结构化事实，避免在主线程反复 JSON 编码和散列长转写。
- 已完整校验的日期保留正文、输入与来源映射缓存；切换日期、回到前台、模型／语言设置改变不清空档案，也不重复读取未变日期的全文。导航导致上一日期的 UI 投影消失，不等于来源删除。选日片段加载后隐藏原始录音及同组兄弟文件、切到其他日期后恢复原始录音，均属于展示替换；保留旧正文，由完整日期来源读取判断真实变化。没有发生展示替换的来源删除仍立即隐藏受影响正文。时区变化导致自然日范围改变时重新校验。
- 控制中心／通知遮罩产生的短暂 inactive 不作为数据恢复：健康快照保持，Runtime 的处理恢复只在首次启动和实际后台返回触发。Watch 状态刷新复用已打开的录音库，不重扫文件或广播虚假的资料变动；存储首次打开／恢复、新录音导入和实际编辑仍通知资料变化。飞行模式不影响本机已保存回顾的读取。
- 冷启动／显式重新读取优先校验当前日期，并立即发布该日结果，再补齐历史档案；历史日期读取失败只影响该日期，不能清空其他日期已确认的回顾。已有正文在普通事实刷新期间保持展示；明确修改、删除或撤回权限时先隐藏受影响旧文再校验，不把读取失败当成删除写回 SQLite。
- 事实变化按日期失效输入缓存。内容片段的说话人绑定、手动编辑、删除与录音会话删除另发证据变更版本，触发完整重新校验，避免被普通进度去重隐藏；来源权限改变清除内存档案后重新验证。校验可能清除失效旧正文，但不会恢复自动尝试次数。
- 存储不可用单独传递：隐藏未经确认的旧文、取消进行中的工作，保留 SQLite 已存档案；恢复后重新读取。冷启动及必要的来源校验仍会读取日期资料，并非永久只查回顾表。
- 列表一次渲染只准备一份合并选择顺序与资格集合，行复用该结果，避免每行重复投影全天转写。该优化不改变分段、回顾生成或合并资格规则。
- 切日读取验证见[2026-11-03 记录](../../../apps/wrist-notes/verification/2026-10-23-persisted-timeline-recap-refresh.md#recap-date-cache-20261103)；此前真机性能边界见[2026-11-02 记录](../../../apps/wrist-notes/verification/2026-10-23-persisted-timeline-recap-refresh.md#ui-lag-20261102)。

## 模型窗口与等待状态（2026-11-02）

- 自定义模型按 `AIConfiguration.contextWindowTokens` 预算；未填写时保守采用 4,096 tokens。附近 Mac 暂按 8,192，ChatGPT 暂按 4,096；暂未通过服务端目录动态发现窗口，不凭模型名称猜测。Apple 使用 `SystemLanguageModel.contextSize`。
- 完整预算包含系统指令、日期说明、资料、消息边界、750 tokens 输出、估算输入的 25% 安全余量，以及一次引用修复所需的 300 字符候选和编号白名单。自定义接口与 Apple 的实际输出上限均为 750；Mac/ChatGPT 现有 transport 尚未提供按调用设置输出上限，预算是保守预留。
- 使用中英文混合估算，代替固定 1,800 字符分批。Apple 在 iOS 26.4+ 额外调用原生 `tokenCount` 检查实际指令与 prompt；26.3 使用保守估算。第三方没有统一 tokenizer，估算不保证等于其真实计数。
- 全部获准摘录能放下时，一次请求直接生成最终回顾；超出窗口才分批提取证据，再按同一预算合并，最多 8 轮。整条资料不因预算不足被静默丢弃；最小请求仍无法放入时明确报告窗口不足。
- 原始长文本仍采用首／中／尾各 200 字符摘录，大窗口不会自动改为上传完整转写。每批保留来源编号；合并仅允许引用该批笔记实际保留的编号。
- 生成界面显示核对资料、整理批次、合并批次和保存阶段。全轮最长等待 300 秒，超时取消任务、保存失败提示、允许手动重试；迟到响应不能覆盖后续结果。后台／录音等既有取消规则仍生效，没有增加无限后台运行。
- 首页在空闲时展示上次失败／中断提示，避免把失败表现为从未生成。待转写、摘录条数仅展示在界面覆盖信息中，不放入模型的生活证据，以免被生成成用户待办。

后续架构方向：复用统一的模型驱动、上下文预算、超时和诊断层；Ask AI 使用工具循环，每日回顾保留确定的批处理流程。本次尚未把各业务迁移到同一 Agent Runtime。

## 用户视角与发言人归属（2026-11-02）

- 用第二人称、2–3 段自然语言，围绕真正有意义的 1–3 件经历回顾工作、学习与生活，不强行凑齐领域，不以日期、系统统计、数字清单开头。健康数值适度取整，只保留有助于理解当天节奏的部分。
- 将地点地址与时间顺序、步数、训练、可归属的对话组合起来，允许推断可能去过的地方、地点之间的移动及当天节奏；在具体推断旁自然使用“看起来／可能”。单独步数不证明目的地，地点采样不证明完整路线、驾驶身份、停留时长或到访目的；家／公司标签需要已有明确依据。
- 睡眠与活动可以支持温和的休息和生活作息建议；没有多日基线时不写趋势，不把单日数字当成疲劳、疾病或心理状态的诊断。最多 1–2 条切实建议，以邀请式语气衔接在结尾，优先用户明确未完成事项。
- 发言人标记逐句跟随摘录。短录音读取当前有效联系人绑定、手动名字和本人声纹标记；长内容片段在同一 SQLite 读取快照内读取 source-scoped 联系人绑定，并检查绑定 revision。只传显示名字／现有组织名称，不传手机号、邮箱或头像。过期绑定不进入输入。
- “用户本人”才可支持本人表达；联系人绑定说明对方身份，不能自动当作本人。“手动命名”不证明亲属或同事关系。未确认身份只回顾讨论主题，不能把录音中的出差、考试等安排直接写成用户任务。长录音的 speaker ID 不与短录音声纹 ID 猜测匹配；无明确绑定时保留未知。
- 请求说明按生成时本地日期区分“昨天／今天／那天”，避免昨日经历写成今天。没有可用本人发言或主动闪念时，除提示约束外拦截已观察到的少量显式归属句式，最多修复一次；仍不合格则拒绝保存新正文。空白闪念和不匹配当前原文的身份投影不能放宽约束。这是有限防错，不证明模型已完整理解人物关系或每项建议归属。
- `DayRecord.attributedTranscript` 与 `ContentProvenance.TextSpan.speaker` 为可选投影字段；老 JSON 可直接解码，不修改 SQLite 表结构或原始 ASR。只有回顾证据加载启用此投影，普通列表和 Ask AI 保留原路径。日期投影先裁剪发言，长文本首／中／尾每个摘录边界重新标记发言人，避免截断后错归属。
- 发言人归属加入回顾证据摘要，撤销／变更绑定后旧归属不能继续通过校验；自动尝试次数不恢复。新 Prompt 不自动重写已保存回顾，用户手动更新应用新表达。
- 引用校验兼容已有 `[1,2]` 格式并校验每个编号，新输出优先 `[1][2]`；编号存在只证明引用范围合法，不能取代对自然语言事实和推断质量的复核。
- 生成语言取 `settings.interfaceLanguage`：简体中文、英文、日文。系统指令与请求末尾均明确指定目标语言，禁止无故混用；中间笔记和最终回顾均用 NaturalLanguage 检查主要语言，错误语言最多修正一次，仍不匹配则明确报错并拒绝保存新正文。语言检测只验证主语言，不保证每个外语词都是合理专名。
- 切换界面语言会使进行中的旧语言请求失效；已保存回顾保留原版本及 language 元数据，手动更新后生成当前语言，不因语言切换打破每日一次自动尝试规则。
