# Mac 会议本地说话人分离

类型：产品与技术方案 · 状态：用户已确认，已实现；执行验证通过，真实归属效果待校准 · 更新：2026-11-13

## 目标与范围

在现有 Mac 会议原文中显示同一场会议内的说话人，保持跨音频分块的编号一致。使用本地音频模型，不上传录音，不依靠 LLM 猜测身份。支持当前75分钟MP4补做说话人分析，不重新运行Whisper；不会因此重新生成或覆盖已有总结。

本轮包含：说话人1、2等稳定标签、单场会议内重命名、按时间戳回放、分析状态与重试、结果持久化。跨会议联系人匹配、本人声纹登记、联系人同步和分离出独立人声音轨不在本轮范围内。“分离”指逐字稿归属标注，不是音源分离。

## 方案比较

| 方案 | 优点 | 代价与限制 |
| --- | --- | --- |
| SpeakerKit/Pyannote分段 + WeSpeaker跨分块匹配（推荐） | 复用iPhone现有实现和固定模型目录，离线，适配长会议 | 需处理模型资源、跨窗口聚类和不确定归属；实际准确率需多人音频验收 |
| 只用SpeakerKit逐块编号 | 接入较少 | 每块编号可能重置，75分钟会议容易出现同人不同号；不满足稳定编号目标 |
| 同时建立跨会议联系人声纹库 | 可识别反复参加会议的联系人 | 新增登记、用户确认、误匹配纠正和生命周期；超出本次会议内区分范围 |

## 用户体验

- 新录制：Whisper完成后，若本地说话人模型可用则自动分析，然后进入总结。说话人阶段失败不阻止阅读原文或单独生成总结。
- 旧会议：原文页增加“区分说话人”；可单独开始、停止、重试，显示独立进度/错误，不把说话人失败等同转写失败。
- 原文每段显示“说话人1”等中性标签，同一标签保持统一颜色。可在当前会议内重命名，例如主持人、张三；名称不自动成为跨会议身份。
- 无充分证据、明显重叠或一段原文覆盖多个相近发言时显示“未确定”。不按字符比例虚构说话人切分，不改写原文内容或原有时间戳。
- 相邻同一说话人的短段只在展示层合并，底层原文ID/文字/时间保持不变。
- 已保存结果重开直接加载，不重复推理。再次分析完成前保留上一版标签；重新聚类后旧手工名称标为待复核，不套用到可能变化的编号上。

## 本地实现

- Mac新增独立的说话人模块，接入当前固定WhisperKit0.18.0包内SpeakerKit产品；复用iPhone模型清单和许可证，不直接引入iPhone UI/联系人/存储模块。
- Pyannote资源约11,242,906字节，WeSpeaker约7,954,144字节，固定版本与哈希校验。模型库提供明确下载/取消/失败状态；推理配置`download:false`，无云端回退。
- 音频只解码有界窗口，建议每个核心窗口约5分钟、边缘少量重叠；用现有最长60秒reader逐段拼接，单次推理输入设硬上限。原始视频始终只读。
- Pyannote识别局部发言区间；从单人有效语音提取WeSpeaker特征，以兼容模型版本、相似度和候选差距进行跨分块匹配。阈值先沿用iPhone保守规则（0.90相似度/0.10差距）作为待实测基线，不宣称为已校准准确率。
- 只保存有质量依据的会话级特征；同一窗口内同时发言的不同局部说话人不得合并成同一全局身份。证据不足时保持未确定，不能用相同局部编号代替声纹匹配。
- 发言区间映射到已有原文ID，按有效重叠分配，接近并列/覆盖不足时不强行归属。稳定编号按首次可靠出现时间生成。
- 说话人任务与ASR/LLM串行调度，重型工作离开MainActor。暂停LAN服务不影响本机处理。

## 存储与恢复

单场会议目录新增独立`speakers.json`，记录版本、音频指纹、原文版本指纹、模型版本、分析状态、分块进度、区间、标签/名称及会话级特征。原有`analysis.json`和MP4保持兼容。原文/音频变化时禁止套用旧标注，提示重新分析；未发生变化时不用重跑ASR。

分块检查点与当前结果分离：取消或退出保留可恢复的已完成分块；完成后原子发布新版本。损坏结果不覆盖；缺失模型、不确定标签、处理失败与总结失败分别显示。退出等待活跃分析安全结束，保留录制文件。

已保存总结不自动改写。后续用户明确重新总结/提问时，使用当前已确认说话人标签和原文；名称仅为用户给当前会议设置的称呼。

## 验收

1. 自动测试：旧会议兼容、边界重叠去重、跨窗口局部编号置换、同窗不同人不合并、平局/无语音/重叠未知、取消恢复、原文版本变化失效、重开不重跑、损坏文件保护、命名复核。
2. 原生Mac编译、签名校验；测试使用临时存储和已安装模型，不静默下载权重或发布LAN服务。
3. 已知两人交替发言样本：人工核对至少一处A→B→A及跨窗口返回同一人的标签；单人样本和重叠样本确认不过度归属。
4. 当前75分钟MP4：完整有界处理、不重新转写、原文/媒体哈希不变、结果持久化。没有人工speaker真值时只能证明全流程完成，不能声称准确率通过。
5. 安装前检查无活跃录制，保留旧App；更新本机测试版，不推送或发布。

## 当前证据

iPhone的`LocalTranscriptionService`、`SpeakerTranscript`、`AudioSpeakerMapping`、`VoiceEmbeddingEngine`已有本地分段、标注和声纹匹配实现。Mac目前的`MeetingTranscriptSegment`没有speaker字段，也没有说话人模型管理或分析状态。用户于2026-11-13确认，正在实施；长会议总结的既有失败是独立问题。
