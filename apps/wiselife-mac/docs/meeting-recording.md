# Mac 会议录制

类型：当前产品与技术说明 · 更新：2026-11-13 · 适用：原生 Mac App，macOS 15+

## 当前范围

会议列表 → 录制设置 → 屏幕／窗口选择 → 录制 → 结束保存 → 详情回放已接入原生 SwiftUI App。使用系统 ScreenCaptureKit，不使用网页模拟画面。编译和合成媒体测试通过；已验证一条用户实际窗口录制的文件解码、播放器推进和详情页构建。录制结束回放崩溃已通过显式链接 AVKit 修复；新的完整录制操作与实际声音效果仍待现场复测，见[验证记录](../verification/README.md#meeting-capture-20261112)。

- 「即时录音」预设仅麦克风，确认设置后开始。
- 「录制会议」第一步设置名称、仅录音／屏幕与音频、系统声音及麦克风，至少开启一个音源。
- 仅录音直接开始，不出现屏幕选择器。
- 屏幕与音频进入 macOS 系统选择器，允许 Entire Screen 或 Application Window，确认范围后开始。取消返回设置，不创建会议文件。
- 录制中可切换应用页面或关闭主窗口，侧栏和菜单栏可返回录制、结束录制。
- 结束后等待系统完成写入，再验证媒体可播放，显示时长、文件大小及回放控件。
- 会议列表和搜索读取本地记录，重启后保留。详情可在 Finder 中显示文件。
- 结束保存后自动使用本地 Whisper 转写，已安装说话人模型时区分发言者，最后使用本地 MLX LLM 总结。已有会议可点击「生成原文与总结」。原文时间戳可跳转回放。
- 「原文／总结」标签读取持久结果；重开不会重复生成。可停止、继续整理或明确重新总结。模型缺失时显示模型库入口，不回退到云端。
- 会议页面包含可折叠、整页高度的 Ask AI；问答仅使用当前会议资料并保存在本机。长会议已有有效说话人结果时，使用当前标签的原文选段；按提问中的名字优先筛选，否则检索相关发言。选段不能代表全部发言，未命中的内容不能断言未提及。尚无说话人结果时使用已有总结，回答说明资料范围；当前每次提问独立，不把历史对话作为模型上下文。
- 上传文件、跨会议联系人识别、行动项执行尚未实现。总结中的待办仅是供核对的文字，不会创建日历或任务。

## 原生布局与本地整理

全局采用白底、浅灰边框和中性控件；220pt 左栏收起为保留菜单图标的 56pt 导航。品牌行的 × 是唯一左栏折叠入口，中间页头没有重复图标；折叠栏顶部可展开。会议媒体紧接录制时间，原文／总结位于播放器下方；右侧 Ask AI 可折叠。

模型库提供 Tiny、Base、Small 语音模型及现有 Qwen3 语言模型。下载必须由用户明确触发，固定版本、大小和哈希校验，推理只读取本机模型及 tokenizer，不上传录音或原文。关闭局域网服务仍可进行本机推理；本机任务与 iPhone 请求共用串行 LLM 队列。

音频读取按解码包的实际时间戳放入固定长度窗口，保留首尾／中间空隙，不拼接挤掉静音；兼容音轨略短于视频以及几个采样点的解码舍入。ASR 每次解码最多 60 秒为 16kHz 单声道，逐块保存原文、绝对时间戳和进度，允许恢复已完成部分。Whisper 的 30 秒模型窗口会补零，末尾时间戳可能略超实际音频；保留与真实音频相交的片段并裁齐末尾，过滤完全位于补零区的结果，不因这类边界估计中断整块。NaN、倒序、负时间和超出模型窗口的异常值仍拒绝。长原文分块摘要后逐层压缩，不静默丢弃尾部；压缩失败保留原文和上次总结。没有有效语音时不生成总结。总结要求依据原文、保留时间戳和引文，未提及的决定／待办不补写；小模型仍可能误解，需核对。

当前为录制结束后处理，未实现录制中实时转写。ASR 与模型工作异步执行，切换页面不会丢失进度。正常退出会等待正在收尾的录制文件保存，再取消并等待推理停止。

## 当前会议说话人（2026-11-13）

模型库新增约19.2 MB的说话人模型，需要明确下载。已转写会议在原文上方点击「区分说话人」，无需再次运行 Whisper 或改写总结。完成后显示「说话人1／2…」、颜色与时间戳；点击名字可改名或留空恢复默认。命名只用于当前会议。界面同时显示已标注／未确定段数，这个数量不是识别准确率。新录制在已有模型时自动分析；模型缺失或说话人失败不会阻止原文／总结保存。多人同时说话、语音太短或归属不可靠的原文保留为「未确定」，不强行分配。

SpeakerKit处理300秒核心窗口、前后各最多2秒上下文，音频分次读取；WeSpeaker以完整10秒及至少2秒尾段提取特征，至少2秒核心独立发言才用于匹配。跨窗口匹配余弦至少0.90且比第二候选高0.10；中间模糊区不新建身份。真实75分钟样本仅211/2631段获得自动归属，当前保守基线仍需有人物真值的样本校准。模型标签是推断，需要听原文核对；不代表联系人身份，也不生成分离后的独立音轨。

`speakers.json`单独保存状态、窗口检查点、发言区间、原文行归属与名字。停止／退出后保留已完成窗口，可继续；重新分析时保留旧结果直到新结果完整发布，旧名称仅供核对，不自动套到新编号。媒体全文件SHA-256、原文与策略版本共同校验；变更或校验失败立即撤下标签。损坏文件不覆盖。模型推理与LLM加载／生成／卸载、ASR共用进程内串行入口，取消等待底层操作真正退出；切换页面不会取消处理，正常退出等待名称保存。

模型只在明确下载时联系固定来源，推理完全在本机。声纹特征限于当前会议检查点，不上传、不建立联系人声纹库。第三方来源与许可见[SpeakerKit](../Sources/CompanionSpeakers/SpeakerModels-NOTICES.txt)和[WeSpeaker](../Sources/CompanionSpeakers/VoiceIdentityModels-NOTICES.txt)。

## 采集与权限

`MeetingKit` 将存储、媒体检查和采集与原有 MLX 功能分开。屏幕模式使用 `SCContentSharingPicker` 提供明确的单屏／单窗口范围，再通过 `SCStream` + `SCRecordingOutput` 写入 H.264 MP4，最高长边 1920 像素、30 fps，保留宽高比和光标。麦克风和系统音频按用户开关配置，排除本应用回放声音。

仅麦克风模式使用 `AVAudioRecorder` 写 AAC M4A。仅录音且包含系统声音时，通过 `SCStream` 只注册 audio／microphone 输出，不注册屏幕帧输出；两种音源分别写入，再按采样时间戳混合为 M4A。系统声音仍可能需要 macOS「屏幕与系统音频录制」授权，跳过选屏不等于跳过授权。

麦克风使用系统授权提示；拒绝或系统采集失败显示可操作错误。原有 App Sandbox 保留，新增 audio-input entitlement 和麦克风／屏幕采集用途说明。不会代替用户授予权限或自动选择任意用户窗口。窗口捕获时的音频范围、设备切换和音画同步需要真实回放验收。

## 数据与生命周期

正常存储位置为 App container 内 Application Support 下的 `WiseLifeMacCompanion/Meetings/<UUID>/`。当前每场会议使用原子写入的 `meeting.json` 和 `recording.mp4`／`recording.m4a`，没有引入新的 SQLite schema。另有 `analysis.json`，保存状态、分块原文、总结、ASR/LLM 标识、处理错误和问答消息。分析文件损坏时阻止重试覆盖，原文件保留；结果原子写入，重启将未结束的整理标记为可继续。音频合成保留 `system-source.m4a`／`microphone-source.m4a` 作为恢复源；不自动上传，也不删除源文件。

先保存会议元数据，再启动采集。结束时先写入 finalizing，完成媒体校验后才写 saved；无效／未完成文件保持 interrupted。视频有画面但无音轨时给出缺失音轨提示。系统中断、主动退出、Mac 休眠均触发停止收尾。强制终止后再次启动会将 recording／finalizing 标记为 interrupted，保留文件，允许用户尝试恢复可播放文件；恢复不能保证修复损坏的 MP4，也不会自动重新录制。

原 Bundle ID、Keychain、模型、配对和用户数据路径不变。本轮不迁移旧数据。

## 开发验证

```sh
cd apps/wiselife-mac
sh scripts/test_meetings.sh
open -n ~/Applications/EurekaLife-Meetings-Debug.app --args --meeting-test --page 会议
```

`test_meetings.sh` 把 MeetingKit 与专项测试复制到临时目录，用无外部依赖的小包运行。仅使用临时目录、合成视频和合成音频，不采集设备、不下载模型或发布 LAN 服务。

Debug 的 `--meeting-test` 使用 container 临时目录 `EurekaLifeMeetingAcceptance`，并使原有 CompanionModel 进入隔离预览状态，不读用户配对钥匙串、不启动模型／网络。录制仍是真实 API；该参数在 Release 中不生效。正常录制文件持久保存，测试目录可能被系统清理。

现场最小验收：录制会议 → 屏幕与音频 → 选择无敏感内容的测试窗口 → 录制 10 秒 → 结束 → 详情播放。分别检查整个屏幕、单窗口、声音、取消选屏、仅录音跳过选屏、重启后回放。不要把合成 MP4 测试当成 ScreenCaptureKit 实测。

## 视频存储体积（2026-11-13）

当前原生采集仍为 MP4 / H.264，最长边 1920、最高 30fps，系统输出默认音频码率。MP4 是容器，单纯改成 MOV 不会明显减小文件；需要调整编码、帧率或码率。Whisper 只分块读取音轨，视频大小本身不是转写输入大小。

对一条 4530.73 秒真实录制的探测：1920×1268 H.264，视频约 1.514 Mbps，48kHz 双声道 AAC 约 247 kbps，总计 1,000,944,932 字节。三个分布在开头、中间、末尾的 30 秒片段以 HEVC、15fps、视频目标 800kbps、AAC 96kbps 转码，总码率约 0.889–0.926 Mbps；该选择保留分辨率、降低动态画面的流畅度，不承诺任意画面都获得相同比例。

建议会议文档／幻灯片录制采用 MP4 + HEVC（hvc1）、原分辨率、15fps、AAC 96kbps；快速演示或动态内容保留30fps。仅需声音时直接选择「仅录音」，不要为了总结保留视频。HEVC 的旧设备兼容性低于 H.264；实际可读性应检查小字与动态场景。本次完整副本为 510,562,661 字节（510.6 MB），比原件减少 49.0%；HEVC 平均约 802kbps，AAC 约96kbps。视频仍为1920×1268，15fps。生成的是独立压缩预览，不覆盖录制、不自动改变新录制默认值。最终实测与长音频修复见[验证记录](../verification/README.md#long-meeting-asr-20261113)。
